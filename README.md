# CQB Tactical FPS

SWAT 4 テイストのブラウザ完結型 3D CQB タクティカル FPS（Three.js + TypeScript + Vite）。

室内クリアリング、左右リーン、段階的なドア開閉・ブリーチング、フラッシュバン、警告コール（コンプライアンス）、非致死性装備、人質交渉、部隊指示（Squad）、現行犯逮捕、そして交戦規定（RoE）に基づく評価をブラウザ上で軽量に体験できます。

## 起動・ビルド方法

Node.js（v20 以降推奨）環境で以下を実行します。

```bash
# 依存パッケージのインストール
npm install

# 開発サーバー起動（Vite）
npm run dev

# 型チェック（strict モード）
npx tsc --noEmit

# 本番ビルド（型チェック＋バンドル）
npm run build

# ビルド結果のローカルプレビュー
npm run preview
```

| `1` | プライマリ武器切替（カービン ⇔ SMG） |
| `2` | 非致死性装備切替（ペッパーボール銃 ⇔ テーザー） |
| `3` | 交渉無線の装備 / 解除 |
| `4` | フラッシュバンの構え / 解除 |
| `Z` / `X` / `V` / `B` | 交渉中のコマンド（`Z`: 説得 / `X`: 要求確認 / `V`: 威圧 / `B`: 切断） |
| `M` | ミニマップの表示切替（プレイ中のみ） |

| `Enter` | ブリーフィング画面で突入開始 / リザルト画面でリトライ |
| `Backspace` | 全容疑者制圧後、未保護の民間人や未回収の証拠を残して手動でミッション終了 |

## 収録ステージ

突入前ブリーフィング画面およびリザルト画面からステージを切り替えられます。多階層ステージではブリーフィング画面のフロアタブ（初期表示 `1F`、`B1` / `1F` / `2F`）で全階層の間取りを事前確認でき、プレイ中のミニマップもプレイヤーの現在階層に合わせて自動切り替えされます。

| ID | ステージ名 | 構成・特徴 |
| --- | --- | --- |
| `stage01_office` | **Stage 01: 雑居ビル 事務所フロア** | 屋外踊り場から突入する L 字型オフィス。受付ロビー・西会議棟・東サービス通路・施錠サーバー室を制圧。 |
| `stage02_house` | **Stage 02: 郊外のL字型邸宅** | 前庭・私道から開始する L 字型ヴィラ住宅。ガレージ勝手口と正面玄関の 2 経路からギャラリー廊下と LDK・主寝室を制圧。 |
| `stage03_warehouse` | **Stage 03: 複合型物流倉庫** | 屋外トラックヤードから突入する物流拠点。多層遮蔽の保管フロアと資材室・管理室をクリアリング。 |
| `stage04_townhouse` | **Stage 04: 二階建てL字邸宅（ガレージ棟付）** | 前庭から東側 1F ガレージ棟と 2F 建て本宅・階段ホールを制圧する立体 CQB ミッション。 |
| `random_small` | **Random Small: コンパクト住宅（ランダム）** | `generators/house_compact.json` によるモジュラー生成ステージ（平屋 / 2F 建て / B1+1F の最大 2 階層構成）。 |
| `random_house` | **Random House: 大型ヴィラ住宅（ランダム）** | `generators/house.json` によるモジュラー生成ステージ（平屋 / 2F 建て / B1+1F / B1+1F+2F の全 4 階層構成）。 |
| `random_embassy` | **Random Embassy: 大使館複合施設（ランダム）** | `generators/embassy.json` による大規模モジュラー生成ステージ（全 4 階層構成・最大 2 階段コア・中庭・地下保管庫対応）。 |

## 🦹 容疑者モード（籠城 vs SWAT）

ブリーフィング画面の `MODE:` で **容疑者（籠城 vs SWAT）** を選ぶと、立場を逆転して立てこもり犯として SWAT 4 名を迎え撃てます（URL: `?mode=suspect`、全ステージ対応・ランダム生成ステージも可）。

- **開始位置**: ステージの容疑者配置のいずれか（突入地点から遠いほど選ばれやすい）。本来の突入地点・隊員配置が SWAT の進入地点になります。
- **準備フェーズ（20 秒）**: ドアを施錠して籠城の準備。`Space` で準備を切り上げて即突入させられます。
- **勝利条件**: SWAT 全員の無力化（撃退）、または突入から 4 分間の生存（籠城成功）。
- **敗北条件**: 死亡。`Space` 長押し（1.5 秒）で投降することもできます。
- **SWAT AI**: 2 人 1 組で部屋を順に掃討し、足音・ドア音・銃声を聞きつけて調査、目撃情報は無線で全隊に共有。施錠ドアはブリーチし、突入時や潜伏推定位置にはフラッシュバンを投げ込みます。全区画を探しても見つからない場合はドローンの熱源探知で大まかな位置を掴みます。傍受した SWAT 無線は画面右下に表示されます。
- **人質**: 民間人が射線上にいる間、SWAT は発砲しません（位置は把握されます）。民間人を撃つと減点。

| 入力 | 機能（容疑者モード） |
| --- | --- |
| `F`（タップ） / `ホイール` | ドア開閉 / 段階開閉 |
| `F`（長押し） | 照準先の閉じたドアを施錠・解錠（施錠ドアは SWAT がブリーチするまで通れない） |
| `Space` | 準備中: 準備完了（即突入） / 突入後: 長押しで投降 |
| `1` / `4` | 主武器切替（カービン ⇔ SMG） / フラッシュバン |

## 交戦規定（RoE）とランク評価

- **加点項目**: 容疑者の現行犯逮捕（`+50`）、証拠武器の回収（`+10`）、無傷の民間人保護（`+30`）、敵対行動後の正当防衛による無力化（`+10`）
- **減点項目（RoE 違反）**: 警告なしの発砲（`-25`）、投降者・拘束済み容疑者への発砲（`-50`）、民間人への非致死性誤射（`-25`）、民間人への致死誤射（`-100`）
- **ランク評価**: ステージごとの理論最大スコアに対する到達率（`roe.json` の `minRatio`）で評価されます。
  - `S`: 85% 以上 / `A`: 65% 以上 / `B`: 40% 以上 / `C`: 15% 以上 / `D`: 15% 未満
- **ミッション終了条件**: 全容疑者が制圧（逮捕または無力化）された後、生存民間人の保護と逮捕容疑者の証拠回収がすべて完了すると自動終了します。残項目がある状態でも `Backspace` キーでいつでも手動終了できます。

## データ駆動アーキテクチャ

マップ・武器・AI・交渉・部隊・RoE などのパラメータはすべて `public/data/` 配下の JSON で管理され、起動時に `DataLoader` がスキーマおよび相互参照を検証します。

```text
public/data/
├── stages.json          # ステージ一覧マニフェスト（選択 UI に自動反映）
├── maps/                # 固定ステージ定義（部屋・壁・床・階段・ドア・遮蔽物・人物・ブリーフィング）
│   ├── stage01_office.json
│   ├── stage02_house.json
│   ├── stage03_warehouse.json
│   └── stage04_townhouse.json
├── generators/          # モジュラー建築生成テンプレート（type: "modular"）
│   ├── house_compact.json
│   ├── house.json
│   └── embassy.json
├── weapons.json         # 実弾・非致死性装備・フラッシュバンのパラメータ
├── ai_profiles.json     # 容疑者・民間人の士気・戦闘・人質盾・パニック設定
├── squad.json           # 味方隊員 AI（スタック・突入・警戒・階段追従）のパラメータ
├── negotiation.json     # 交渉選択肢・成功率係数・タイムアウト設定
├── perception.json      # AI の聴覚・視覚パラメータ
├── player.json          # 移動・足音・リーン・警告コール・逮捕/保護パラメータ
├── doors.json           # ドア高・ピーク角・開閉速度・ブリーチ設定
└── roe.json             # 交戦規定の配点・ラベル・ランク閾値（minRatio / minScore）
```

### 新規ステージの追加方法

コード変更なしで新しいステージを追加できます。

1. `public/data/maps/<stage_id>.json` を作成する（既存マップの形式に準拠）。
2. `public/data/stages.json` の `stages` 配列に `{ "id": "<stage_id>", "name": "...", "description": "..." }` を追記する。

### ランダム間取りステージ（モジュラー建築生成・多階層・敷地8変換）

`stages.json` のエントリに `"generator": "<generator_id>"` を指定すると、`maps/` の固定 JSON の代わりに `public/data/generators/<generator_id>.json` のテンプレートとシードから決定論的にマップを生成します（生成結果は固定マップと同一の `validateMap`・相互参照検証を通過。従来の `type: "house"` テンプレートとも後方互換を維持）。

- **モジュラー空間合成と動線グラフ（`type: "modular"`）**:
  - 玄関・折返し2レーン階段コア・廊下・LDK・ビルトインガレージ・中庭・寝室/スイート・書斎/執務室/会議室・地下倉庫/金庫・2Fルーフテラスなどの建築モジュールを、動線グラフ（全域木＋閉路ループ動線・隣接/禁止ルール・サブ室分割）に沿って格子スナップ単位（`snap`: `0.25m` / `0.5m`）で辺接着パッキングします。
  - 外窓・扉（`doors.json` 統一扉高・施錠率）・アーチ開口・遮蔽物（家具）・容疑者/民間人配置も可動域クリアランスを守ってシードから一括生成され、万一通常試行が上限に達した場合も選択済み階層構成を維持する決定論的最小構成器がフォールバックとして成立を保証します。
- **多階層バリエーション（`B1` / `1F` / `2F`）と階層別独立フットプリント**:
  - テンプレートの `storyProfiles` 重みに応じて、**平屋（`[0]`：1Fのみ）・2階建て（`[0, 1]`：1F+2F）・地下付き平屋（`[-1, 0]`：B1+1F）・3階層（`[-1, 0, 1]`：B1+1F+2F）**が選択されます（`house_compact` は平屋 / 2F / B1+1F の最大2層構成、`house`・`embassy` は全4構成、`embassy` は最大2階段コア対応）。
  - ガレージ等の平屋屋根制約（`flat_roof_only`）、2層吹き抜け（`double_height`）、2Fセットバックおよびルーフテラスにより各階が単なるコピーにならない立体構造を形成し、階段の人体掃引頭上クリアランス・床スラブ開口・落下防止壁・地下スラブ音響遮蔽・Squad の多階層階段経路探索と連携します。
- **敷地直交8変換（回転・鏡映）**:
  - 原点 `(0, 0)` 中心対称（`2 * snap` 整数倍）の敷地上で、建物全体の直交回転（`0° / 90° / 180° / 270°`）× 左右鏡映（反転有無）の**全8通りの直交変換**を格子整数座標系で無誤差適用します。突入アプローチの方角・初期スポーン・味方隊員展開位置・扉ヒンジ/開放方向・外窓法線・階段進行方向がすべて連動して変化します。
- **シードの扱いと JSON 調整**:
  - ステージ選択や「別の間取りを生成」で新しいシード、リトライ（`R`）では同じシードを使用します。ブリーフィング画面にシードが表示され、シード入力欄・URL（`?stage=random_house&seed=12345`）・コンソールから同じ間取りを完全再現できます。
  - 階層プロファイル重み・目標面積・建築モジュール（寸法・個数・家具・サブ室）・動線ループ数・敷地変換規則・施錠率・人数などはテンプレート JSON のみで調整できます。
